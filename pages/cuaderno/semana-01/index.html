01 / PUNTO DE PARTIDA

Mi mapa para
este curso.

Al revisar el sílabo entendí que el curso conecta dos partes: primero la interfaz que utilizo en el navegador y después la lógica del servidor y el consumo de APIs. Esta primera semana me da el vocabulario para comprender ambas.

Lo que busco comprender

  • Distinguir una página, un sitio, una aplicación y un sistema web.
  • Relacionar DNS, TCP/IP y HTTP con lo que sucede al abrir una dirección.
  • Reconocer los roles frontend, backend y fullstack.
  • Organizar mi entorno de trabajo y el portafolio educativo.
Cómo se organiza el aprendizaje +

El material plantea usar Teams para el aula virtual, WhatsApp para comunicados, una laptop propia y GitHub para el portafolio. Mi responsabilidad es contar con acceso a los recursos, participar en el equipo y entregar las actividades a tiempo.

El sílabo distribuye cada promedio parcial en evaluación de logro (50 %), laboratorios y prácticas (25 %), y trabajo de investigación y portafolio (25 %). Por eso, documentar el proceso forma parte del aprendizaje.

02 / IDEAS FUNDAMENTALES

No todo lo que abro
es lo mismo.

Para ordenar los conceptos, los relaciono con ejemplos cercanos. Las categorías pueden superponerse; lo importante es reconocer su alcance.

01

Página web

Un documento que el navegador interpreta. Esta entrada de la semana 1 es una página.

02

Sitio web

Un conjunto de páginas relacionadas. Mi portada y las semanas del cuaderno forman un sitio.

03

Aplicación web

Me permite realizar tareas e interactuar con información, como reservar una cita o gestionar un pedido.

04

Sistema web

Integra procesos, usuarios y módulos de una organización; por ejemplo, matrícula, pagos y notas.

Internet ≠ Web

Internet es la infraestructura que conecta redes. La Web es uno de los servicios que la utiliza. Un navegador me da acceso a documentos y aplicaciones sobre esa infraestructura. [1]

Nativo y web: dos formas de llegar al usuario

El software nativo se desarrolla para una plataforma concreta y suele instalarse en ella. Una solución web utiliza tecnologías que interpreta el navegador. No lo reduzco a «con conexión» o «sin conexión»: algunas aplicaciones web también pueden ofrecer funciones sin Internet.

Las piezas que construyen una página

<HTML>

Estructura y significado

Organizo títulos, párrafos, enlaces y secciones. HTML es un lenguaje de marcado.

{ CSS }

Presentación

Defino colores, espacios, tamaños y la adaptación de la página a distintas pantallas.

JS ( )

Comportamiento

Respondo a eventos y actualizo la interfaz, como al cambiar el modo de color.

La web abierta tiene más herramientas +

La Open Web Platform reúne estándares abiertos que permiten construir para distintos navegadores. Intervienen organizaciones como W3C, IETF, Ecma International y Unicode Consortium. La interoperabilidad depende de especificaciones compartidas. [2]

XML
Representa e intercambia información estructurada.
SVG y WebGL
SVG describe gráficos vectoriales; WebGL permite gráficos 2D y 3D mediante una API.
MathML
Representa expresiones matemáticas.
WAI-ARIA
Comunica roles, estados y propiedades de accesibilidad cuando el HTML nativo no basta.
Web APIs
Permiten trabajar con el DOM y capacidades del navegador.
03 / CÓMO FUNCIONA LA WEB

Lo que pasa
después de Enter.

Así resumo una navegación HTTPS habitual. Es un recorrido simplificado: la caché y la versión del protocolo pueden cambiar algunos pasos.

◎https://ejemplo.test/EJEMPLO ILUSTRATIVO
  1. DNS · Busco la dirección

    El navegador necesita resolver el nombre del dominio a una dirección IP, si no dispone ya de esa información en caché.

  2. Conexión · Preparo el camino

    IP permite encaminar los paquetes. En HTTP/1.1 y HTTP/2 se usa TCP; HTTPS añade TLS para proteger la comunicación. HTTP/3 utiliza QUIC sobre UDP.

  3. Petición · Solicito un recurso

    El cliente envía una petición HTTP, por ejemplo GET, para obtener el documento.

  4. Respuesta · El servidor contesta

    Recibo un estado, cabeceras y, cuando corresponde, contenido. Un 200 indica éxito; un 404, que no se encontró el recurso solicitado.

  5. Renderizado · Veo la página

    El navegador interpreta HTML y CSS, solicita otros recursos y ejecuta JavaScript cuando corresponde.

El ejemplo no envía peticiones reales. Repaso la infraestructura con MDN [1] y los protocolos en las especificaciones HTTP.

04 / ROLES Y HERRAMIENTAS

Dos lados.
Una misma aplicación.

EN EL NAVEGADOR

Frontend

Construye lo que veo y con lo que interactúo: estructura, estilos, formularios y comportamiento de la interfaz.

HTML · CSS · JavaScript

EN EL SERVIDOR

Backend

Procesa las solicitudes, aplica reglas de negocio, valida datos y controla el acceso a la información.

Python · PHP · Java · Bases de datos

Fullstack: trabaja en ambos lados y entiende cómo se conectan. No significa que todo deba resolverse con una sola tecnología.

También aprendí a distinguir UI y UX

UI es la interfaz: botones, tipografía, colores y componentes. UX es la experiencia al realizar una tarea. En mi portafolio, el color pertenece a la interfaz; encontrar una semana sin perderme forma parte de la experiencia.

Mi mapa inicial de herramientas +
Control de versiones
Git registra cambios; GitHub aloja repositorios y facilita la colaboración.
Gestor de paquetes
Organiza dependencias del proyecto.
Herramientas de construcción
Preparan o transforman recursos para su uso en la aplicación.
Librerías y frameworks
Aportan componentes o una estructura de trabajo. Primero necesito comprender qué problema resuelven.
05 / LABORATORIO 01A

Preparar el espacio
para construir.

El sílabo propone reconocer la interfaz de Visual Studio Code, las extensiones y los atajos. Esta es mi guía de repaso para trabajar de forma más ordenada.

  1. Abrir la carpeta completa.

    El explorador me permite ver archivos y carpetas del proyecto, no solo un documento aislado.

  2. Ubicar las áreas de trabajo.

    Distingo la barra de actividad, la barra lateral, el editor, el panel y la barra de estado.

  3. Buscar comandos y extensiones.

    Uso la paleta para encontrar acciones y reviso qué aporta cada extensión antes de incorporarla.

  4. Separar contenido, diseño e interacción.

    Organizo HTML, CSS y JavaScript para que sea más fácil localizar y modificar cada parte.

06 / MI REFLEXIÓN

Lo que me llevo
de esta semana.

¿Qué aprendí?

Ahora puedo separar la estructura, la presentación y el comportamiento de una página. También entiendo que abrir una web implica comunicación entre el navegador y un servidor, y que DNS y HTTP cumplen funciones diferentes.

¿Cómo lo aprendí?

Organicé los conceptos del material y los relacioné con este portafolio: una semana es una página, el cuaderno reúne varias páginas y el cambio de apariencia es una interacción. Explicarlo con un ejemplo propio me ayuda a conectar la teoría.

¿Qué necesito seguir practicando?

Quiero observar peticiones en las herramientas del navegador, ganar fluidez con VS Code y mejorar la estructura de mis páginas. Mi siguiente paso es profundizar en HTML, XML y CSS.
